# Auto-Checkin

会員専用サイトのチェックインボタンを、GitHub Actions で毎日 1 回だけ自動で押す仕組みです。
Public リポジトリなら Actions の実行時間は無料・無制限なので、費用はかかりません。

## 仕組み

`checkin.py` が Playwright（ヘッドレス Chromium・iPhone として振る舞う）で

1. `TARGET_URL`（サイトURL）を開く
2. ログイン画面に飛ばされたら ID / パスワードを入力して送信し、もう一度チェックインページへ
3. 「チェックイン」「訪問」「スタンプ」などのラベルを持つボタンを探してクリック
4. 押した後の表示、またはボタンが消えたことで成功を確認

という流れを実行します。失敗しても最大 3 回まで自動でリトライします。

**押し済みの日は何もしません。** ボタンが無く「チェックイン済」「また明日」等の表示がある場合は
「本日は既に済み」と判断して正常終了するので、1 日に複数回動いても二重に押すことはありません。

**サイトがメンテナンス中のときは失敗扱いにしません。** ボタンが無く「メンテナンス中」等の表示がある場合や、
サイトが HTTP 502 / 503 / 504 を返した場合は、リトライせずに警告（黄色の ⚠ 注記）を出して正常終了します。
次回の定時実行（00:10 / 12:10）で改めて押しにいきます。両方ともメンテナンスに当たった日は押せていないので、
警告が出ていたらメンテナンス明けに手動実行してください。

## セットアップ

### 1. Secrets を登録する

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で 3 つ登録します。

| Name | 値 |
| --- | --- |
| `USER_NAME` | サイトのログイン ID |
| `USER_PASSWORD` | サイトのパスワード |
| `TARGET_URL` | サイトURL |

Secrets は Public リポジトリでも他人からは読めず、ログ出力時も自動でマスクされます
（さらにスクリプト側でも伏せ字にしています）。

### 2. 動作確認する

**Actions** タブ → **Daily Check-in** → **Run workflow** で手動実行します。

今日はもう手動で押してしまっているので、期待される結果は次のログです。

```
本日は既にチェックイン済みでした（判定語: ...）。何もせず終了します。
```

これが出れば **ログインもページ取得も成功している** ということです。明日以降は自動で押されます。

失敗した場合は下の「うまく動かないとき」を参照してください。

### 3. 以降は自動

`.github/workflows/checkin.yml` の cron で、日本時間 **00:10** と **12:10** の 1 日 2 回動きます
（GitHub の cron は混雑時に数十分遅れたり、まれにスキップされることがあるため保険で 2 回にしています。
押し済みなら何もしないので実害はありません）。

## うまく動かないとき

サイトの HTML を実際に確認できない状態で書いているため、ボタンやフォームの特定は
**ラベルの文字列からの自動判別**にしています。ここが外れた場合は、ログに

- 今開いている URL とページタイトル
- ページ上のクリックできる要素のラベル一覧

が出ます。この一覧を見て、正しいボタンのラベルやセレクタが分かったら、
**Settings → Secrets and variables → Actions → Variables** に以下を追加すれば
コードを触らずに調整できます（すべて任意）。

| Variable | 用途 | 例 |
| --- | --- | --- |
| `CHECKIN_SELECTOR` | チェックインボタンを CSS セレクタで直接指定 | `form#visit button` |
| `CHECKIN_TEXTS` | ボタンを探す語をカンマ区切りで指定（既定を置き換え） | `今日の訪問,訪問する` |
| `ALREADY_TEXTS` | 「押し済み」と判定する語 | `本日は訪問済みです` |
| `SUCCESS_TEXTS` | クリック後に成功と判定する語 | `訪問ありがとう` |
| `MAINTENANCE_TEXTS` | 「メンテナンス中」と判定する語 | `ただいまメンテナンス中です` |
| `EXCLUDE_TEXTS` | 誤クリック回避のため無視する語 | `履歴,ランキング` |
| `LOGIN_URL` | 最初に開く URL をログインページにしたい場合 | サイトURL/login/` |
| `USER_SELECTOR` / `PASS_SELECTOR` / `SUBMIT_SELECTOR` | ログインフォームの入力欄・送信ボタンを直接指定 | `input[name="login_id"]` |

ページ本文そのものを見たい場合は、手動実行時の **debug** を on にしてください。
ただし **Public リポジトリの実行ログは誰でも読めます**。会員名などが本文に含まれる可能性があるため、
既定では本文を出力しません（ボタンのラベルのみ出力）。確認が済んだらログを削除するのが安全です。

## 知っておくとよいこと

- **失敗の通知**: GitHub は cron 実行のワークフローが失敗するとメールで知らせてくれます
  （claude.ai ではなく GitHub の Settings → Notifications → Actions で設定を確認できます）。
- **60 日ルール**: Public リポジトリでは、リポジトリに 60 日間まったく動きがないと
  スケジュール実行が自動停止されます。停止前に GitHub からメールが来るので、
  そこから再有効化するか、たまに何かコミットしてください。
- **Secrets を平文で書かない**: `checkin.py` やワークフローに ID / パスワードを直接書くと
  Public リポジトリでは全世界に公開されます。必ず Secrets 経由で渡してください。
- サイト側の仕様変更（ボタンの文言変更など）で動かなくなることはあります。その場合は上記の
  Variables で調整してください。
